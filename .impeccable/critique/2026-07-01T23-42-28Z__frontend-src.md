### Anti-Patterns Verdict

The "Liquid Stage" neon-dark-glass identity is genuine and brand-intentional — not generic dark mode. But the execution has recognizable AI tells:

- Gradient text (`.cta-heading span`, `ScoreOverlay.css`, `Dashboard.css`) — 5 instances flagged by detector
- Side-tab accent border (`.admin-sidebar-link.active` with `border-left: 4px solid #00f5ff`)
- Numbered section badges ("01"/"02"/"03" on How It Works steps)
- Hero-metric strip (100% / ∞ / QR / ⚡ in identical containers)
- Identical card grid (3 glass cards with icon + heading + description)
- Bounce easings (2 instances in RoomMobile and RoomTV)
- Layout transitions on height/width in Dashboard.css

Detector confirmed: 247 findings (231 advisory, 16 warnings). The most severe: 178 undocumented colors and 53 undocumented border-radius values across 20+ files, meaning the DESIGN.md tokens are aspirational — the actual code uses inline values that don't match the system.

### Overall Impression

The emotional core is strong — the glass-neon-dark identity genuinely conveys nightclub energy and the Phone/TV dual-interface is a smart product architecture. But the surface is over-decorated with AI-native patterns (gradient text, conic borders, shimmer masks, numbered badges) and the design system exists in theory but not in practice (178 colors in code vs. ~12 in DESIGN.md). The biggest opportunity: strip decorative noise, enforce the token system, and lower the join barrier to match the "zero social friction" promise.

### What's Working

1. Emotional identity is coherent — the neon-dark-glass system with drifting blobs and glow effects creates genuine nightclub energy, directly serving the "Party IS the interface" principle.
2. Dual-interface architecture (Phone=control, TV=stage) is the product's best design decision — the mobile remote and TV spectacle are clearly differentiated.
3. Real-time reliability — WebSocket + HTTP polling fallback + visibility-change reconnection shows deep understanding of the party scenario.

### Priority Issues

- [P1] Guest registration friction — Asking for email AND phone to sing karaoke violates "zero social friction." Strip to name-only for guests.
- [P1] Design token drift — 178 undocumented colors in 20+ files vs. 12 tokens in DESIGN.md. RoomMobile.tsx alone has 64 inline color values.
- [P1] Cognitive overload on RoomMobile — 3 tabs + search + now-playing + queue + cooldown + host controls + name change in one viewport.
- [P2] No help/onboarding system — Heuristic 10 scored 1/4. No tooltips, no onboarding, no explanation of participant vs TV mode.
- [P2] Gradient text + decorative bloat — 5 gradient-text instances, conic-gradient border animation, shimmer mask, 3 background blob animations.
- [P3] Admin panel visual drift — Admin uses separate language (cyan accent, monospace, no glass, raw Tailwind, sidebar blue border).
- [P3] Gray-on-color contrast — text-gray-600 on bg-red-500 in AdminDashboard.tsx fails WCAG contrast.

### Minor Observations

1. RoomTV.tsx uses deprecated `<marquee>` tag — use CSS instead
2. `.btn-neon-border` conic-gradient animation is GPU-expensive for low-end devices/projectors
3. `TruncatedText` duplicated in RoomMobile.tsx and RoomTV.tsx — extract to shared component
4. Stats strip mixes semantic ("100%") with decorative ("⚡") values in identical containers — undermines credibility
5. RoomMobile's now-playing uses hardcoded gradients (#7c4dff → #ff4081) outside the token system
6. The TV "click to activate" overlay reappears on every page load, not just first visit
